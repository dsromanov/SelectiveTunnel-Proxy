# Проверки прокси-версии — 17 сентября 2026

Выполнены на Windows x64, в целевом Windows PowerShell 5.1, с настоящим sing-box 1.14.0. Итог: **11 групп проверок прошли**.

1. Конфигурации SOCKS5, HTTP CONNECT и HTTPS с TLS принимаются движком через stdin.
2. Обычный маршрут остаётся direct; TUN не получает default routes; DNS обычных адаптеров не перенастраивается конфигом; UDP выбранных доменов отвергается, а DoH направлен через прокси.
3. Пустые/неправильные данные входа, порты вне диапазона, HTTPS без имени сертификата и дополнительные CIDR отвергаются.
4. Windows DPAPI выполняет шифрование/расшифровку, замену пароля и отказ на повреждённом blob; сохранённые байты не содержат открытого логина/пароля.
5. Отсутствие URL списка правил не препятствует работе и не запускает внешнюю загрузку.
6. Подписанные изменения проходят проверку; подмена и повтор отвергаются; ранее выбранные домены сохраняются.
7. Настоящий SOCKS5/RFC1929 handshake с локальным тестовым сервером проходит; выбранный домен идёт через upstream, постороннее назначение обрабатывается напрямую.
8. Неверный SOCKS5 пароль вызывает ошибку без обращения к доступному прямому origin.
9. HTTP proxy authentication и CONNECT проходят на локальном тестовом сервере, сохраняется прямой маршрут для постороннего назначения.
10. Неверный HTTP proxy пароль вызывает ошибку без прямого fallback.
11. Реальный DNS listener возвращает FakeIP A/AAAA и пустой HTTPS-ответ без реальных IP hints.

Все PowerShell-файлы прошли синтаксическую проверку. Для русских строк сохранена кодировка UTF-8 с BOM, совместимая с Windows PowerShell 5.1.

Использовались только фиктивные логин/пароль тестового сервера и loopback-соединения. Реальные данные пользователя и API аккаунта не использовались. Дочерние тестовые процессы остановлены. NRPT, firewall, сетевые адаптеры и системные маршруты рабочей машины не изменялись.

**Не проверено:** реальное подключение к Proxys.io, TLS самого прокси, работа UDP у провайдера, GUI/установщик с повышением привилегий, запуск от SYSTEM, Wintun/постоянные loopback-маршруты, обрывы на физических адаптерах, функциональность нативных приложений, два ПК и 10 устройств одновременно. Для этого нужен этап приёмки из ACCEPTANCE.md после ввода актуальных данных.

Проверка HTTPS-прокси здесь — проверка конфигурации, не живой TLS-handshake. DPAPI проверена в текущем Windows-контексте LocalMachine, не отдельным процессом SYSTEM. Локальные тесты не доказывают отсутствия любых утечек в реальной системе с собственным DNS приложений.
